I want to create a post-optimizer for written littleman (.man) programs.
It would need to have five main featues:
- Create a graph representation of the current program. We need to parse the ascii and create a graph of rooms connected to eath other. We can use/or reference existing logic for that
- Run a set of heurstics to try to optimize each room contents. We need to deeply understand all the glyphs that are possible, their behavior and potential counterparts/equivalent/mirrored logic.
Ideally that would mean creating a representation of inner logic in terms of a graph as well, which we then can place optimally using a subset of heuristics (i.e. the paths that little man takes to go between commands). We can also have "macro" heuristics that replace a combination (not a single) command with a shorter one (or even a bigger one, which could help pack the whole room better).
- Try to compact the placement of optimized rooms in such a way that minimizes the max(widht, height) of the whole solution. This has a set of constraints. The inputs/outputs to pipes connections are determined by manhattan distance, which means rearranging the pipes might break those. The pipes can only >=2 long. Also, in some cases the programs rely on the length of the pipe (i.e to store a certain nubmer of values in it). We need to be able to determine what constraints each pipe has, and take it into account when optimizing. Also, in case of displays, the pipes have to be connected to a certain side of the display.
- Once we have an optimized solution, we need to be able to run it on the engine to validate it (did the logic break) and whether it scores better or worse vs the original one. We might even try to use it as a utility function for our heuristic, but keep in mind that it's not instant, which might be an issue for large number of versions.

Do a deep research on the specs of the engine we're working with, the constraints, the current code we already have, the existing .man programs and suggest the best approach.
Break it down and ideally suggest tasks that we can parallelize between agents (i.e. one agent could look at "backpack" logic and define the requirements for modeling/optimizing its commands).
